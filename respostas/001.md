# Respostas — Feature #001 — Hardening de Segurança, SQLite Nativo e Concorrência

<!-- tearform v2 -->
## A. Persistência e Migração de Dados (SQLite)

**A1.** Como devemos tratar a migração dos dados legados do db.json?

> Importar automaticamente registros de db.json para o SQLite no primeiro arranque (seed suave)

**A2.** Qual modo de Journaling do SQLite devemos configurar?

> Modo WAL (Write-Ahead Logging) — concorrência máxima de leitura e escrita

---

## B. Concorrência e Regra de Reserva de Vagas

**B1.** Como a API deve responder se duas requisições tentarem reservar a última vaga simultaneamente?

> A primeira confirma (HTTP 200) e a segunda recebe HTTP 409 Conflict ('Não há vagas disponíveis')

---

## C. Segurança, Sessões e Autenticação

**C1.** Qual formato de transporte do Token JWT nativo (HMAC-SHA256)?

> Header Authorization: Bearer <token> gravado em sessionStorage/localStorage

**C2.** Qual o tempo de expiração recomendado para a sessão?

> 24 horas (ideal para expediente de trabalho em academia)
